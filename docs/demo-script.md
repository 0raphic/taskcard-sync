# 三分钟演示稿

> 目标：让评委在 30 秒内看懂「纸卡 → 扫码 → 网页同步」，剩下两分半解释它为什么值得做。

## 0:00 开场（举卡）

（拿起一叠打印好的卡，抽一张举起来）

「我每天的任务写在这种卡上——1/8 张 A4，能塞进口袋，能贴在桌上。纸的好处是：看得见、写得上、不用解锁手机。

坏处也明显：**它不会统计，不会提醒，更不会同步。**」

## 0:20 问题

「所以大家最后都回到了 App：打开手机、找 App、解锁、点进列表——为了勾一个勾，花 15 秒。

我们想要的其实很简单：**纸的手感，数字的同步。**」

## 0:40 方案

（把卡翻到正面，指右上角二维码）

「每张卡右上角有一个码。它指向的不是一串任务 ID，而是一个短链——**短码和任务分开存**，所以任务改了、库换了、甚至明年重做系统，这张纸还能用。

扫一下，就是这张卡本身。」

## 1:00 现场演示

先用「打印 8 张任务卡样张」这张卡（右上角短码 `a7K2m9`）：

1. 手机（自带相机）扫 `a7K2m9` → 落地页出现标题、截止、材料
2. 点「✓ 做完了」→ 按钮变红章
3. 转头看笔记本：看板上这张卡已经进入「已完成」分组，**没有刷新**

「一秒内。这不是我按了什么快捷键，是 PocketBase 的实时订阅推过来的。」

4. 反向：电脑上点进任意一张卡改成「进行中」→ 手机落地页同步变化

「两个方向都通。这就是多端同步——现在只有两个浏览器窗口，但换成手机 App，协议不变。」

5. 补一刀：打开「录入」，把卡上的字粘进去 → 点「解析成任务」→ 标题/截止/用时/材料都拆好了 → 保存，
   自动生成新短码，下一版卡片就能印出来。

## 2:00 背后（只讲三点）

- **实时**：PocketBase 单文件后端，SQLite + SSE，局域网里一台笔记本就能跑
- **纸卡是生成的**：Python + reportlab，A4 一页 8 张，虚线裁剪，二维码 ≥15mm；改字段不用重排版
- **录入**：把卡上的字粘进网页，DeepSeek 拆成结构化字段；断网时用内置规则拆，照样能演

## 2:40 收尾

「一张 A4 八张卡，成本几分钱；后端是一个 exe。

下一步：把网页换成 Flutter 客户端（同一套 schema），再把打印做成小店能下单的模板。

**纸不会消失，它只是终于联网了。**」

## 演示前 5 分钟命令

```bash
# 1) 确认后端与网页都活着
curl -s http://127.0.0.1:8090/api/health
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8088/

# 2) 若数据库被动过，重置成演示数据（幂等）
pnpm seed

# 3) 打开两个窗口
start http://127.0.0.1:8088/
start http://127.0.0.1:8088/t/a7K2m9
```
